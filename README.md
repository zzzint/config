# config

Sets up a machine for omp: two plugins from this repository's marketplace, and app settings linked into place.

```sh
git clone https://github.com/zzzint/config ~/Documents/config
~/Documents/config/link.sh
```

`link.sh` symlinks every file in `dotfiles/` to where its app reads it, moving any existing file aside as `<name>.bak-<time>`, then adds the `zzzint` marketplace and installs `pstack@zzzint` and `zstack@zzzint`. It is safe to run again. `./link.sh --check` reports a link that is missing or that an app replaced with a plain file.

## Layout

| Path | What it is |
|---|---|
| `.omp-plugin/marketplace.json` | The `zzzint` marketplace catalog |
| `plugins/pstack/` | poteto's pstack for omp, generated by `build/pstack/` (see its README) |
| `plugins/zstack/` | My own skills (`charcuterie`, `contextualize`, `council`, `recap`), `grill` from [mattpocock/skills](https://github.com/mattpocock/skills) (MIT), and rules (`global-safety`, `browser`) |
| `build/zstack/version.mjs` | Gives zstack a new version; the `zstack` workflow runs it on every push that changes `plugins/zstack/` |
| `dotfiles/omp/` | `AGENTS.md`, `config.yml` and `mcp.json` for `~/.omp/agent/` |
| `dotfiles/tern/settings.json` | Tern, at `~/Library/Application Support/Tern/` |
| `dotfiles/zed/keymap.json` | Zed, at `~/.config/zed/` |

omp saves settings through the `config.yml` link into this repository, so changes made in `/settings` show up here as uncommitted edits.

The Dynatrace MCP server reads its token from the macOS keychain through `security`; a new machine needs that keychain item before the server connects.

## Changing zstack

Edit under `plugins/zstack/`, commit and push. The workflow stamps a new version on `main`, keeping the base version from `plugins/zstack/.claude-plugin/plugin.json` (change the part before `-` there to start a new base); pick it up with:

```sh
omp plugin marketplace update zzzint
omp plugin upgrade zstack@zzzint
```

zstack ships only a Claude-format manifest (`.claude-plugin/plugin.json`) for the same reason pstack does: a root `plugin.json` would drop every skill marked `disable-model-invocation`. A skill that keeps state writes it outside the plugin, because an upgrade replaces the installed folder; `council` uses `~/.local/state/council/`.
